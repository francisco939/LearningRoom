# 在线自习室产品图谱与横向对比

> 目的：把 Redwatch、Stillwhere 放回整个品类里看，找出「哪些是产品本质、哪些只是风格选择」。
> 信息来源：官网/商店页/公开仓库/实际走查；未公开的实现细节不做断言。

## 1. 三类范式

在线自习室看起来五花八门，本质上在解决三个不同的问题：

| 范式 | 解决什么 | 代表 | 核心机制 | 风险 |
| --- | --- | --- | --- | --- |
| **氛围型** | 「开始难」——坐下、进入状态 | Stillwhere、LifeAt、qiye-study-room | 场景 + 声音 + 计时 + 轻陪伴 | 约束弱，容易变成壁纸 App |
| **监督型** | 「坚持难」——坐住了但会摸鱼 | 凛冬督学局、CoStudy、番茄ToDo | 摄像头/屏幕巡查、学霸模式、座位/离座惩罚 | 隐私、误判、焦虑 |
| **匹配型** | 「一个人学不下去」——需要具体的人 | Focusmate、StudyStream、YouTube Study Space | 1:1 预约、多人视频房、直播席座 | 冷启动、匹配质量、内容审核 |

很多产品是混合的：CoStudy 用「虚拟校园 + 座位」做氛围，用「深度模式/溜号收座」做监督；Stillwhere 用「讨论区 + 在线人数」做弱匹配。

## 2. 逐产品速写

### 2.1 CoStudy（国内，虚拟校园）

- **设定**：一个虚拟校园，按身份分教学楼（小学初中部、高中部、大学部、在职部、综合自习楼），楼内按目标和地区分楼层（考研层、考公层）。
- **核心动作**：进楼 → 选空座 → 填本次目标/专注时长/休息时长/专注模式 → 开始。
- **专注模式**：轻度 / 深度 / 白名单。深度模式切出 App 就算「溜号」，座位会被收走；小休结束不回教室同样算溜号。
- **经济**：按专注时长发「专注工资」Co 币；Co 币买道具、补救。
- **社交**：同桌（邀请链接，自己先落座对方才能找到）、Co伴（同目标/同地区）、小纸条、教室「加油」、咖啡厅语音/文字。
- **记录**：手动结束才算完成；Days 模块看今日/历史、连续天数、日均时长；两次自习之间可写总结。
- **技术**：iOS/Android 原生 App（未公开具体框架）；实时座位状态、房间/楼层是典型的长连接 + 状态同步场景。
- **值得学**：**空间即信息架构**——用「楼栋/楼层」自然完成人群分层，比标签/算法匹配更有归属感。

### 2.2 番茄ToDo（国内，工具型）

- **定位**：极简番茄钟 + 习惯养成，App Store 94 万评分、4.9。
- **核心**：学霸模式（暂时远离手机）、待办清单、白噪音、强制提醒、统计图表、自习室（和朋友一起）、Apple Health「正念训练」。
- **自习室**：偏「熟人一起计时」，不是陌生人空间；无摄像头监督。
- **商业化**：免费 + 内购（会员/主题/高级统计）。
- **值得学**：**工具效率优先**——启动快、无广告、离线可用；自习室只是能力之一，不承担全部留存。

### 2.3 Focusmate（海外，1:1 陪伴）

- **机制**：预约 25/50/75 分钟场次，系统匹配一位搭档，视频开场互报目标，结束互相复盘。
- **关键设计**：**预承诺（pre-commitment pact）** + 具体的人在等你，比「房间」更有约束力。
- **产品**：日历同步、收藏搭档、浏览器内视频（无需装软件）；150+ 国家、1200 万+ 场次。
- **商业化**：免费每周 3 次，付费解锁不限次。
- **技术**：WebRTC 视频 + 预约/匹配系统 + 日历集成；难点在匹配供给与 no-show。
- **值得学**：**把「陪伴」做成一次约定**，而不是一个可以随时退出的房间。

### 2.4 StudyStream / LifeAt（海外，视频自习室）

- **StudyStream**：24/7 的「study with strangers」视频房，打开摄像头就能看到别人在学；有主持人/版规；免费 + 会员。
- **LifeAt**：虚拟学习空间，场景氛围 + 番茄钟 + 待办 + 社区 + 视频房，偏「空间感」。
- **共同点**：视频是主界面，氛围是背景；靠「被看见」产生约束。
- **风险**：隐私、骚扰、审核成本、带宽成本；冷场时体验很差。
- **值得学**：**在场感**（presence）本身就是产品力，但要给「不想露脸」的人留后路。

### 2.5 YouTube Study Space（开源，直播型）

- **机制**：一个 24 小时 YouTube 直播，观众在聊天框输入 `!in` 入座，`!in 英语 min 60` 设定任务和时长，`!break` / `!resume` / `!out` 控制；座位和任务名直接渲染在直播画面上。
- **技术**：Go 服务监听 YouTube Live Chat，维护虚拟座位状态，OBS/直播画面叠加；自动分配座位、超时、排名、会员专属席。
- **优点**：零安装、零注册，参与门槛极低；公开直播带来天然围观与社区感。
- **缺点**：依赖平台；隐私（聊天公开）；无法做私密房间。
- **值得学**：**用最轻的交互（一条命令）完成「入座」**，以及「状态可视化在公共画布上」。

## 4. 架构与实现对比

| 产品 | 前端 | 后端 | 实时 | 媒体 | 部署 |
| --- | --- | --- | --- | --- | --- |
| 凛冬督学局 | Next.js 静态导出 | 自建 REST（nginx + EdgeOne） | REST + 心跳（推断） | COS 直传 + 私有桶 | COS/CDN + 独立 API |
| Stillwhere | Next.js App Router + RSC | Next.js Route Handlers（Node） | SSE | 同源 `/media` + manifest | Cloudflare + 源站 |
| CoStudy | 原生 App | 未公开 | 长连接（推断） | 客户端资源包 | 未公开 |
| Focusmate | Web | 未公开 | WebRTC | 视频 | 未公开 |
| StudyStream | Web | 未公开 | WebRTC | 视频 | 未公开 |
| YouTube Study Space | 直播画面（OBS） | Go + YouTube API | YouTube Live Chat | 直播流 | 自托管 + YouTube |
| qiye-study-room | 原生 JS + 自建构建 | Node + PostgreSQL | 轮询/SSE（未确认） | 本地/静态 | Vercel + 托管 PG |

一个明显规律：**越偏「氛围」的产品，越倾向静态/CDN + 轻后端；越偏「实时陪伴」的产品，越必须长连接/WebRTC。**

## 5. 品类共性抽象

不管哪家，领域模型都能收敛到这几个核心对象：

```
User ──< Session >── Room/Seat
  │         │
  │         ├── Timer（planned / elapsed / status）
  │         ├── Scene（场景/时段变体）
  │         └── Sound（音乐/环境音/白噪音）
  ├──< Presence（在线/专注中/离开）
  ├──< Message（房间/讨论区）
  ├──< Achievement / Honor（成长）
  ├──< Wallet / Inventory（经济）
  └──< Friendship / Squad（关系）
```

五个真正难的部分：

1. **时间权威**：计时必须服务端可校验，否则排行榜/连续天数没有意义。
2. **在场感**：怎么让「有人」这件事真实但不打扰——心跳、人数、状态、消息，都要克制。
3. **约束的度**：太弱没用，太强劝退；Redwatch 用「3 颗星 + 梯度惩罚」解决，CoStudy 用「收座」解决。
4. **内容供给**：场景/声音/皮肤需要持续产出，否则新鲜感消失。
5. **冷启动**：空房间比没房间更劝退；要么官方号撑场，要么先做单人体验。

## 6. 常见反模式

- **自习室变聊天室**：社交入口太重，专注场景被聊天淹没。对策：讨论区默认收起、消息不进主屏、限制长度（Stillwhere 200 字）。
- **用假在线人数充场面**：短期有效，长期毁信任。
- **惩罚过重**：一次失误封禁 8 小时，对轻度用户是劝退；需要宽松档/申诉。
- **摄像头默认开启**：必须先选模式、再授权、可关闭留档、可清空，否则合规和口碑双输。
- **计时器可被本地改时间**：必须服务端结算 + 幂等提交。
- **场景包过大**：首屏几 MB 的视频会直接杀死转化；要懒加载、短视频循环、移动端降级。
- **通知打扰**：专注产品的通知必须极少，否则违背核心承诺。
- **成就通胀**：39 个成就里如果一半是「注册/点按钮」，会稀释稀有度。

## 7. 对 LearningRoom 的启示

1. **先选范式，再选技术**：氛围型/监督型/匹配型的技术栈和成本结构完全不同，不要混着做。
2. **单人体验必须先成立**：没有别人时也好用，才敢做社交；否则冷启动即死亡。
3. **时间与结算服务端化**：从第一天就设计 `session` 的提交/校验/幂等，后面加排行榜、成就、支付都不用返工。
4. **内容与代码分离**：场景/音频用 manifest + 资源包，运营可以换内容而不发版。
5. **在场感用 SSE 起步**：人数、状态、轻消息足够；视频/语音等到有明确需求再上 WebRTC（LiveKit）。
6. **克制**：主界面只留「场景 + 计时 + 一个主动作」，其他都收进抽屉。
